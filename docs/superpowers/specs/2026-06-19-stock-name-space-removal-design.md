# 2026-06-19 股票名称中间被 OCR 识别出多余空格的修复设计规范

## 1. 痛点与异常表现

目前系统在调用 Gemini OCR 大模型解析复盘长图时，受图片中排版、个股字数不同（如 3 个字、4 个字的股票名称）等视觉干扰影响，Gemini 极易输出带有分散空格的股票名称，例如：
* `"张 江 高"` (原为 `"张江高科"` 或 `"张江高"`)
* `"中 青 宝"` (原为 `"中青宝"`)
* `"大 唐 电 信"` (原为 `"大唐电信"`)
* `"* S T 宁 科"` (原为 `"*ST宁科"`)

由于这些多余的空格被原封不动地写入了 D1 数据库的 `limit_up_stocks` 表，这直接导致在进行“个股模糊查询”、“板块热度分析”或“连板梯队”匹配时，由于多出的空格无法精确识别、关联失败。

---

## 2. 解决方案：数据清洗下沉 (Data Cleaning Pipeline)

在 **三层架构 (3-Tier)** 的底层数据解析层，即在纯粹无状态的 `src/utils/ocr-parser.ts` 处理大模型输出 Markdown 时，对提取的 `name` 字符串执行全方位的空白剔除。

### 2.1 股票名称清洗转换
对于表格解析出的 `parts[2]` (即 `name` 字段)：
* 运行全空白清除：`name.replace(/\s+/g, '')`
* **表现与对比效果**：
  | OCR 原始输出 | 清洗后结果 (入库数据) |
  | :--- | :--- |
  | `"张 江 高"` | `"张江高"` |
  | `"中 青 宝"` | `"中青宝"` |
  | `"大 唐 电 信"` | `"大唐电信"` |
  | `"* S T 宁 科"` | `"*ST宁科"` |
  | `"T C L 科 技"` | `"TCL科技"` |

此处的清洗下沉直接能从源头上保证所有落入 D1 数据库的股票名称完美无暇，杜绝一切由于拼写排版导致的前端关联异常。
