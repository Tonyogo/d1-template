# 2026-06-19 上传数据模块极致精简与排版美化规范

## 1. 变革核心

在之前的机制中，系统存在两套流程：旧式的“单图直传+即时OCR”和新式的“极速暂存+延迟处理”。两套流程在 UI 层面存在诸多元素重叠（两个不同的表格控制台、多处重复的日期 input 等），不仅给用户造成决策负担，也让底层代码存有死代码（dead code）。

**本次改造核心**：
1. **统一工作流**：**废除** 旧版直传直解，无论是拖入 1 张图还是 20 张图，业务流有且仅有一条：**拖拽即上传至云端 R2 暂存，随后在表格中预览、微调日期、按需解析**。
2. **消灭后端死代码**：彻底清理后端 `POST /api/upload` 控制器端点及其附属的业务代码。
3. **一屏化排版重构**：重新规划 UI 布局，整合控制台，砍掉冗余进度指示、成功汇总卡片、冗余日期 input，呈现高级、简约、高度集中的现代 Dashboard 体验。

## 4. 交互流升级 (Streamlined Interaction Flow)

1. **拖入/选择文件**：
   - 用户将 A、B、C 三张图片拖入 `drop-zone`。
   - `UploadTab` 立刻过滤图片，并根据每一个 file 新建一条待上传状态，实时压入待处理列表表格中，状态渲染为 `正在上传... (菊花转圈)`。
   - 自动并行发起 `api.batchUpload(formData)` 将文件送到 R2 暂存。
2. **上传完成**：
   - 暂存成功，行状态更新为 `待处理` 徽标。
   - 日期框被赋予默认识别日期（如解析文件名失败则留空），并高亮预警，日期框解锁支持手调。
3. **一键/单张解析**：
   - 点击行解析或“一键顺序处理”，行加载，调用大模型，入库，行伴随优雅淡出特效消失。

这种彻底无感的直观体验极大提纯了业务闭环！
